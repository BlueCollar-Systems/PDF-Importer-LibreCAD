# Source paint contrast in LibreCAD

Actual LibreCAD 2.2.1.5 / Qt 5.15.2 exposed two paint failures: a dark RGB31
panel became adaptive CAD foreground and its white lettering disappeared;
black lettering on an explicit white panel also became adaptive foreground and
disappeared in model view. A PDF's explicit painted background must remain
independent from CAD's useful foreground adaptation.

The exporter now preserves source fill RGB. Exact white source paint is encoded
as RGB254, and exact black fixed paint as RGB1, because LibreCAD treats the
exact endpoints as adaptive colors. This deliberate one-channel approximation
is reported. Ordinary dark-neutral text and strokes retain their existing
adaptive foreground behavior.

Dark text receives fixed source paint only when original PDF drawing order,
character trace, and character quads prove that it is fully inside an earlier
opaque, unclipped rectangular fill, with no intervening overlapping paint.
The proof binds the source PDF, page, source text identity and original ink.
Unknown, translucent, partially covering, nonrectangular and omitted full-page
paper backgrounds do not establish this context. The export-only receipt and
delivered color participate in reporting and glyph-cache identity; repeated
characters inside and outside a panel cannot share the wrong paint. Cancellation
propagates through both proof and export boundaries.

## Real host observations

The source-created white-panel control was generated by clean commit
`2eef01be672ca098230cc081cbb329ab0fadcb13`, without an output-editing wrapper.
Its five changed paint runtime files are byte-identical in integrated commit
`07a1ef02376bccf751ecd12ee70d9ec1d8838a93`.

The native host observer confirmed all of the following on the exact control:

- File > Open: black lettering is readable inside the white rectangle, while
  ordinary black lettering outside it remains the adaptive CAD foreground.
- Print Preview: both source-black labels are black and readable.
- Native Save As to DXF2007, close, and File > Open of that saved path: both
  contexts remain visually readable. The loaded path was checked in the actual
  title/status after reopening.

Independent read-only source-versus-save comparison retains all supported
individual geometry, geometric redraw sequence, text content/layout/visibility,
units, bounds, filled area, XDATA and critical headers. The saved drawing has
zero audit errors and one surfaced orphan PLOTSETTINGS housekeeping fix.
This control has no images; its vacuous image checks provide no image coverage.

Whole-document semantic equivalence remains false. The native writer converts
adaptive entity RGB0 to ACI7, changes a layer's color transport and changes the
used Unicode font-style reference. Those differences remain visible in the
receipt and are not accepted as proof of identical paint or text styles.

An earlier source-created dark-panel control also passed native model view,
Print Preview and close/save/reopen: the RGB31 panel and white lettering were
readable, alongside its black titles, fractions, rotated text, fills, hole,
dash and raster. Its source/save comparison confirms resolved image references
and image pixels/placement when saved beside the existing assets. That older
isolated control still contained the separately repaired FIT-spline issue;
geometry, draw-order, XDATA and some audit checks failed, so this historical
paint observation is not whole-drawing acceptance or cross-folder image proof.
